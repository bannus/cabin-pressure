# Cabin Pressure

A deterministic cabin traffic-management prototype. The current playable
experiment is **The Drinks Run**: a two-minute flight with 16 passengers,
two loos, a drink-service objective, and one forecasted turbulence window.

## Playtest

```sh
npm ci
npm run debugger
```

Open `http://localhost:4173` and start with **seed 42**, then try the next seed.
Set `PORT` to use another port.

- Tap a seated passenger for suggested dispatch; tap a loo to override.
  Leave safe passengers seated when traffic or turbulence makes a trip unwise.
- Pull the cart aside to clear the aisle. Resume it to finish drinks for all
  16 passengers before landing. Each maneuver costs two service seconds.
- Seat belts come on at 65 seconds for 10 seconds, with a 20-second warning.
  People in a loo can finish; everyone else in transit must return.
- A diaper call requires a long loo visit. Reach a loo within 45 seconds.
- Three incidents lose the flight. Fewer incidents earn a better landing
  rating; aim for a spotless flight rather than merely surviving.

The flight starts paused. Space pauses/resumes, `1` / `2` sends the selected
passenger front/rear, and `C` parks/resumes the cart. Setup, seed, speed, and
the event log are under the bottom disclosure. Retry preserves the seed;
Next seed changes the scenario.

The browser bundles `src/playtest.ts` and uses the **same simulation** as the
CLI and tuning runs. There is no separate JavaScript rules implementation.
`public/playtest.js` is generated by the build and is not committed.

## Tuning experiments

```sh
npm run tune
npm run tune -- --seeds 200 --base-seed 10000
npm run tune -- --sweep --seeds 50 --json
```

Every active policy gets at most **one command per two seconds**, including
cart commands. They see current state and estimates, not future RNG draws.
The comparison includes hands-off play, nearest-loo reactive dispatch,
UI-assisted reactive dispatch, anticipatory planning with cart control,
and never-park/always-park ablations. The sweep compares three fill rates
against three loo-duration ranges.

Metrics include survival, **clean wins**, incidents, command count, service
completion, diaper changes, queue depth, parked time, and actual loo occupancy
in 30-second windows. See the [tuning notes](docs/design/06-level-configuration.md)
for the selected configuration and measured results. Bot success does not
establish that the game is fun; this is a candidate for human playtesting.

## Development and legacy harness

```sh
npm run build
npm test
npm run simulate -- --playtest --interactive
npm run simulate -- --seed 42 --duration 180
npm run bot -- --seeds 50
```

The original eight-row `tinyReadableCabin` remains available for regression
tests and the legacy bot comparison. `simulate --playtest` selects The Drinks
Run. Interactive commands: `assign P001 front`, `cart park`, `cart resume`,
`cart start`, `turbulence start`, `pause`, `resume`, `status`, `help`, `quit`.

The engine, dispatch estimates, configurations, and tuning policies are in
`src/`. Browser entry point: `src/playtest.ts`. Tests: `tests/`.
